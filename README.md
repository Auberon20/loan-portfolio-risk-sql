# Оценка риска и резерва по кредитному портфелю

Аналитика кредитного портфеля и упрощённая оценка резерва под потери в стиле IFRS 9 (МСФО 9).

## Данные

Источник - реальный срез выдач Lending Club за январь-март 2018 года (10 000 кредитов), набор `loans_full_schema` из учебного пакета OpenIntro. Файл лежит в `data/loans_full_schema.csv`, зеркало - [Rdatasets на GitHub](https://github.com/vincentarelbundock/Rdatasets/blob/master/csv/openintro/loans_full_schema.csv), оригинальное описание датасета - [OpenIntro](https://www.openintro.org/data/index.php?data=loans_full_schema).

56 полей на кредит: сумма, ставка, грейд (A-G), статус (Current/Late/Charged Off/Fully Paid), доход и долговая нагрузка заёмщика, кредитная история и т.д.

## Как запустить

Нужен локальный PostgreSQL (`createdb loan_reserves`), дальше по порядку из корня проекта:

```
psql -d loan_reserves -f sql/01_schema.sql
psql -d loan_reserves -f sql/02_load_data.sql
psql -d loan_reserves -f sql/03_transform_curated.sql
psql -d loan_reserves -f sql/queries/01_portfolio_overview.sql
...
```

(или любой другой запрос из `sql/queries/` по отдельности).

## Структура

- `sql/01_schema.sql` - сырая таблица `loans_raw`, повторяющая исходный csv один в один
- `sql/02_load_data.sql` - загрузка csv через `COPY`
- `sql/03_transform_curated.sql` - очищенная таблица `loans` (типизация + стадирование по риску) и справочник допущений по PD
- `sql/queries/` - семь аналитических запросов, каждый закрывает отдельный бизнес-вопрос

## Методология и допущения

- Резерв считается по упрощенной логике IFRS 9 - это учебная демонстрация механики расчета на SQL
- `Stage 1` (обслуживается в срок) - резерв = баланс x PD(12 мес.) x LGD
- `Stage 2` (грейс-период, просрочка 16-30 дней) - резерв = баланс x PD(12 мес.) x 3 x LGD (грубый proxy lifetime-PD, не выше 100%)
- `Stage 3` (просрочка 31-120 дней или дефолт) - резерв = баланс x LGD (кредит уже проблемный, PD принимается за 100%)
- LGD зафиксирован константой 55% - типичное отраслевое допущение для необеспеченных потребительских кредитов
- PD по грейдам - иллюстративные цифры (см. `pd_assumptions_by_grade` в `03_transform_curated.sql`), ориентировочно в известных диапазонах дефолтности Lending Club по грейдам
- Граница Stage 2/Stage 3 - учебное упрощение: датасет не разбивает "Late (31-120 days)" мельче, а конвенциональный порог дефолта в IFRS 9 - 90+ дней, поэтому весь бакет консервативно отнесен к Stage 3
- Датасет - разовый срез на одну дату, поэтому нельзя построить настоящую PD-модель или полноценную vintage-кривую по годам
- Реальная методология резервирования в российском банке отличается от использованной здесь логики IFRS 9 и в проекте не воспроизводится

## Результаты и выводы

1. Портфель выглядит здоровым: 10 000 кредитов на $144.6 млн остатка (без учета закрытых), 93.8% кредитов и 97.9% баланса - в статусе "Current", на Stage 2 и Stage 3 вместе приходится около 2.1% баланса портфеля. Но, скорее всего, дело просто в возрасте кредитов: они выданы 1-3 месяца назад, у большинства просто не было времени уйти в просрочку.

2. Резерв по упрощенной IFRS 9-логике - $7.44 млн, или 5.15% от баланса портфеля. Основную его массу (около 80%) формирует Stage 1 - просто потому, что там сосредоточено 98% баланса, и даже небольшой PD, помноженный на такую массу, дает заметную сумму. Это стандартный для банковской риск-аналитики вывод: основной резерв складывается из "ожидаемых" потерь, которые еще не произошли.

3. NPL растет практически монотонно от грейда A к грейду F (0.26%, 0.51%, 0.86%, 1.72%, 2.03%, 7.28% соответственно) - похоже, система грейдов Lending Club действительно ранжирует риск заемщиков. Грейд G не показателен - всего 12 кредитов в выборке.

4. По цели кредита NPL ratio ощутимо разный - медицинские кредиты оказались самым рискованным сегментом (6.04% NPL), за ними major_purchase (2.64%) и house (2.59%). Дежурный debt_consolidation - самый массовый сегмент (4920 из 10000 кредитов) - при этом один из наименее рискованных (0.68%), вероятно, потому что это уже отфильтрованные банком заемщики с достаточно устойчивым доходом для рефинансирования долга.

5. Собственники жилья с ипотекой (MORTGAGE) рискованнее не выглядят - у них NPL ниже (0.51%), чем у арендаторов (1.19%) и собственников без ипотеки (1.29%). Логично: наличие одобренной ипотеки само по себе фильтрует заемщиков по устойчивости дохода.

6. Risk-adjusted доходность растет от A до E, а затем начинает падать в F и G (spread между ставкой и резервом: 5.49% в A, пик 9.69% в E, затем 7.42% в F и 4.63% в G) - для грейдов A-E рынок действительно компенсирует риск повышенной ставкой с запасом, а вот в самых рискованных грейдах ставка уже не полностью окупает риск. Правда, тут очень маленькая выборка (58 и 12 кредитов), делать по ней твердые выводы преждевременно.

7. "Свежие" когорты выдачи (март 2018) показывают меньшую долю проблемного баланса (1.61%), чем более старая когорта (январь, 2.84%) - ожидаемо, у январских кредитов было больше времени накопить просрочку. Это иллюстрирует логику vintage-анализа, хотя для полноценной vintage-кривой нужна история за несколько лет, а тут - только один квартал.
